# Migration Guide v4

Version 4.0 makes the runtime DI-agnostic, redesigns event mediation around handler priority, and renames interfaces. This guide lists the breaking changes and the steps that upgrade a project from v3.x.

The key changes are:
1.  The library is now DI-agnostic, so each container needs its own extension package.
2.  Event handling is redesigned with a new `[HandlerPriority]` attribute and concurrency controls.
3.  Interfaces and properties are renamed.

## Step 1: Update NuGet Package References

Version 4.0 organizes packages around container-specific extensions. Update your `.csproj` files to reference the new extension packages.

In v3.x, the references look like this:
```xml
<PackageReference Include="LiteBus" Version="3.x.x" />
<PackageReference Include="LiteBus.Commands" Version="3.x.x" />
<PackageReference Include="LiteBus.Queries" Version="3.x.x" />
<PackageReference Include="LiteBus.Events" Version="3.x.x" />
```

For Microsoft DI, version 4.0 uses these references:
```xml
<PackageReference Include="LiteBus.Commands.Extensions.Microsoft.DependencyInjection" Version="4.0.0" />
<PackageReference Include="LiteBus.Queries.Extensions.Microsoft.DependencyInjection" Version="4.0.0" />
<PackageReference Include="LiteBus.Events.Extensions.Microsoft.DependencyInjection" Version="4.0.0" />
```

For Autofac, version 4.0 uses these references:
```xml
<PackageReference Include="LiteBus.Commands.Extensions.Autofac" Version="4.0.0" />
<PackageReference Include="LiteBus.Queries.Extensions.Autofac" Version="4.0.0" />
<PackageReference Include="LiteBus.Events.Extensions.Autofac" Version="4.0.0" />
```

## Step 2: Update DI Registration

Module extensions include the core `MessageModule` automatically, so `AddLiteBus` registration needs no explicit message-module step.

In v3.x, registration looks like this:
```csharp
services.AddLiteBus(registry =>
{
    // MessageModule had to be registered explicitly first
    registry.AddMessageModule(module => ...);
    registry.AddCommandModule(module => ...);
});
```

In version 4.0, registration looks like this:
```csharp
services.AddLiteBus(registry =>
{
    // The MessageModule is now added automatically by other LiteBus modules.
    registry.AddCommandModule(module =>
    {
        module.RegisterFromAssembly(typeof(Program).Assembly);
    });
});
```

## Step 3: Replace `[HandlerOrder]` with `[HandlerPriority]`

Version 4.0 removes the `[HandlerOrder]` attribute. Replace every occurrence with `[HandlerPriority]`. The behavior is unchanged. Lower numbers still execute first.

In v3.x, the attribute looks like this:
```csharp
[HandlerOrder(1)]
public class MyPreHandler : ICommandPreHandler<MyCommand> { ... }
```

In version 4.0, the attribute looks like this:
```csharp
using LiteBus.Messaging.Abstractions;

[HandlerPriority(1)]
public class MyPreHandler : ICommandPreHandler<MyCommand> { ... }
```

On `IHandlerDescriptor`, the `Order` property is now `Priority`.

## Step 4: Update `EventMediationSettings`

Version 4.0 restructures `EventMediationSettings` to support the new concurrency features.

In v3.x, the settings look like this:
```csharp
var settings = new EventMediationSettings
{
    Filters = { Tags = new[] { "Tag1" } }
};
```

In version 4.0, the settings look like this. The `Filters` property becomes `Routing`, and the new `Execution` property controls concurrency.

```csharp
var settings = new EventMediationSettings
{
    // Filters are now under the 'Routing' property
    Routing = new EventRoutingSettings
    {
        Tags = new[] { "Tag1" },
        HandlerPredicate = descriptor => ... // Predicate now covers both publish overloads
    },
    // New property to control concurrency
    Execution = new EventExecutionSettings
    {
        PriorityGroupsConcurrencyMode = ConcurrencyMode.Sequential,
        HandlersWithinSamePriorityConcurrencyMode = ConcurrencyMode.Parallel
    }
};
```

## Step 5: Update `ExecutionContext.Items` Key Type

The `Items` dictionary on `CommandMediationSettings`, `QueryMediationSettings`, and `IExecutionContext` now uses `string` keys instead of `object` keys, which improves performance and type safety.

In v3.x, the access looks like this:
```csharp
AmbientExecutionContext.Current.Items[typeof(MyKey)] = "my-value";
```

In version 4.0, the access looks like this:
```csharp
AmbientExecutionContext.Current.Items["MyKey"] = "my-value";
```

## Step 6: Update Custom Mediation Strategies (Advanced)

If you implemented a custom `IMessageMediationStrategy`, update two `IMessageDependencies` member names:

- `Handlers` is now `MainHandlers`.
- `IndirectHandlers` is now `IndirectMainHandlers`.

In v3.x, the access looks like this:
```csharp
var handler = messageDependencies.Handlers.Single().Handler.Value;
```

In version 4.0, the access looks like this:
```csharp
var handler = messageDependencies.MainHandlers.Single().Handler.Value;
```
